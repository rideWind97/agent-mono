面试官你好，我叫盛俊鹏，本科软件工程，7年前端经验。我的经历大概可以分成三条主线：复杂画布、AI交互和前端工程化。

## STAR项目讲述稿

### 1. Buzzy - AI视频生成平台画布生态

S 场景：Buzzy 是 AI 视频生成平台，用户会输入文案、图片或视频，再通过 Agent 和画布节点完成生成流程。问题是 AI 生成链路长、等待感强，如果前端只展示最终结果，用户很难理解当前进度，也难以中途干预。

T 任务：我负责核心画布区和 Agent 对话框，需要把生成过程可视化，同时保证节点、媒体、连接线和对话框状态一致。

A 行动：我设计并实现画布节点系统、动态连接线拓扑、Canvas Player，并打通 Agent 对话框的 SSE / WebSocket 流式反馈和 UI 工具调用链路。为了后续可维护，我还制定了 FPS、内存泄漏、渲染延迟等监控指标，并沉淀画布开发文档。

R 结果：生成流程从“等待结果”变成“过程可视化”，用户能通过节点状态理解进度和操作反馈；同时我自研的 leafer-connector、leafer-player 两个插件被 LeaferJS 官网推荐，说明方案具备一定社区复用价值。

### 2. MasterGo - 复杂画布性能与D2C重构

S 场景：MasterGo 是类似 Figma 的协同设计工具，画布中存在超大文件、多层嵌套图层、评论点、可交互资源等复杂交互，性能和定位准确性直接影响设计师核心工作流。

T 任务：我负责画布重点模块和D2C重构，需要解决超大文件卡顿、复杂坐标联动和D2C历史逻辑臃肿的问题。

A 行动：我先用 Performance 定位主要瓶颈，再落地多级缓存、虚拟列表、分层分块、非视口裁剪等优化；坐标问题上，我处理世界坐标、视图坐标、多层嵌套相对坐标之间的联动；D2C 方向，我重构轻量 DSL，并引入 AI 辅助生成，减少模板硬编码。

R 结果：复杂画布 FPS 稳定性明显提升，评论点和可交互资源在缩放、拖拽场景下定位更稳定；D2C 重复逻辑清理后，相关代码量下降约30%，后续维护成本降低。

### 3. super-aicc - 工程化治理

S 场景：公司 10多个业务项目长期独立演进，存在 Vue2、Vue3、React 多技术栈并存、规范割裂、组件重复建设、新人上手成本高的问题。

T 任务：我作为前端工程化负责人，需要在不影响业务持续交付的前提下，推动前端底座统一。

A 行动：我主导引入 pnpm workspace Monorepo，统一 lint、目录规范、依赖管理和共享包发布；用 qiankun 微前端支持新老应用灰度共存；建设 yiwise-design Vue/React 双版本组件库、Storybook 文档、Design Token 和 Atomic CSS。

R 结果：10+ 产品线的视觉和交互规范逐步收敛，新组件开发效率提升约30%，跨项目组件复用成本下降约50%，新人接入成本也明显降低。

## 面试官追问时的展开顺序

### 1. 如果问“你最有技术深度的项目是什么？”

优先讲 MasterGo 或 Buzzy。讲法按这个顺序：

1. 为什么这个问题难：大文件、多层嵌套、实时交互、AI生成链路。
2. 你怎么定位问题：Performance、性能指标、状态链路拆解。
3. 你具体做了什么：缓存、虚拟列表、分层分块、坐标转换、流式渲染。
4. 结果是什么：FPS稳定性、代码量下降、插件沉淀、用户体验改善。
5. 复盘是什么：指标前置、文档沉淀、让团队后续能复用。

### 2. 如果问“你在团队里的角色是什么？”

你可以这样说：

我通常不是纯执行角色，而是会承担“方案设计 + 核心模块编码 + 推进落地 + 文档沉淀”的角色。比如画布项目里，我会先拆出性能、交互、数据状态和可维护性几个关键点，再把高风险模块自己先跑通，同时把实现规范和边界沉淀成文档，方便组员接入。工程化项目里，我也会从规范、依赖、发布、组件复用和新人上手成本几个维度推进。

### 3. 如果问“为什么想来字节？”

你可以这样说：

我想来字节主要有两个原因。第一，字节有很多高复杂度、高用户规模的创作和AI产品场景，这类场景对前端不只是页面还原，而是要求交互、性能、工程化和业务理解一起发挥作用，和我过去的经验比较匹配。第二，我希望在更强的技术环境里继续提升自己，把过去在画布、AI交互、工程化上的经验放到更大规模的产品里验证和迭代。

### 4. 如果问“你最大的短板是什么？”

建议回答：

我过去更深的是前端复杂交互、画布和工程化，对偏底层图形学或完整后端系统的深度还在持续补齐。但我的优势是学习和落地速度比较快，遇到新问题会先把业务目标、技术边界和可验证指标拆清楚，再通过小步验证推进。比如做AI交互和AICR时，很多能力也是在项目中快速学习并落地的。

## 临场提醒

- 少说“负责”，多说“我解决了什么问题、怎么判断问题、做了什么取舍、结果如何”。
- 数据不确定时不要硬报，改成“约”“明显”“稳定性提升”“代码量下降约30%”这种你能解释的口径。
- 字节面试很容易深挖，讲项目时一定主动把“难点、方案、结果、复盘”说完整，不要只背简历。
