## 1）Agent 是什么

与“单轮问答”不同，Agent 的核心是**持续决策循环**：

1. 观察当前状态（用户输入、工具返回、记忆）
2. 思考下一步策略
3. 选择并执行动作（调用工具/交给子 Agent/向用户提问）
4. 获取新观察并继续循环，直到满足终止条件

## 2）Agent 常见分类

### ReAct

- 特点：每一步都做“思考 + 行动”
- 优点：透明、可调试
- 适合：多工具交互、需要逐步推理的问题

### Plan-and-Execute

- 特点：先产出计划，再按计划执行
- 优点：结构更稳定，适合中长任务
- 风险：计划不准时会连锁偏差

### Multi-Agent

- 特点：多个角色 Agent 协作（如规划、检索、评审）
- 优点：分工清晰，可扩展
- 风险：通信成本、冲突协调复杂

## 3）ReAct 核心循环

标准链路：

- Observe：读取用户目标、上下文、记忆
- Think：判断下一步是“继续问用户”还是“调用工具”
- Act：执行工具或动作
- Observe：读取工具结果，更新状态

实践建议：

- 每轮循环记录 `thought / action / observation`
- 设定 `maxSteps`，防止无限循环
- 工具失败后要有重试与降级策略

## 4）工具选择与编排

关键原则：

- 工具契约清晰：参数 schema、输出结构、错误码
- 工具职责单一：一个工具只做一件事
- 工具编排可观测：记录每次调用原因与结果

常见编排模式：

- 串行：A 的结果作为 B 输入
- 并行：多个工具同时调用后聚合
- 条件分支：根据中间结果选择后续工具

## 5）多 Agent 协作模式

### Supervisor 模式

- 一个主管 Agent 负责拆分任务 + 分配给专家 Agent
- 适合“目标明确、角色分工稳定”的场景

### Swarm 模式

- Agent 间更平等，按任务标签自组织协作
- 适合“任务动态变化、需要灵活接力”的场景

## 6）Agent 记忆系统

### 短期记忆（Short-term）

- 一次会话中的临时上下文
- 常用：最近 N 轮对话 + 工具返回摘要

### 长期记忆（Long-term）

- 跨会话的偏好与事实
- 常用：用户档案、常用配置、历史成功方案

建议：

- 短期记忆偏“即时状态”
- 长期记忆偏“稳定事实”
- 对长期记忆增加写入策略（何时写、写什么、多久过期）

## 7）安全与可控性

### Guard Rails

- 输入校验：长度、敏感词、注入特征
- 工具权限：危险操作强制阻断
- 输出约束：结构化输出、脱敏

### Human-in-the-loop（HITL）

- 对高风险动作进行人工审批
- 常见触发条件：
  - 删除/转账/生产发布
  - 外部系统写操作
  - 高金额或高影响变更

## 8）本仓库可运行示例

参见：`examples/agent-learning`

包含 4 个学习场景：

1. ReAct Agent（完整 Observe→Think→Act 循环）
2. Plan-and-Execute Agent（先计划后执行）
3. Supervisor 多 Agent（主管调度专家）
4. Swarm 协作（角色接力完成任务）

同时内置：

- 短期/长期记忆
- guardrails 风险拦截
- HITL 审批模拟

## 9）建议学习顺序

1. 先跑 ReAct，看循环与工具轨迹
2. 再跑 Plan-and-Execute，看“计划”价值
3. 再跑 Supervisor / Swarm，对比协作差异
4. 最后关注安全：触发高风险输入，观察 Guard Rails + HITL

## 10）进阶实践建议

- 接入真实工具（搜索 API、日历、代码执行沙箱）
- 给 Agent 加评估指标（任务完成率、平均步数、工具失败率）
- 引入轨迹回放（trace replay）做问题复盘
- 将记忆持久化到数据库并加入生命周期策略
