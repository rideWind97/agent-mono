# RAG 概览

RAG 是 Retrieval-Augmented Generation 的缩写，中文常叫检索增强生成。它的核心思路是：不要让模型只依赖参数记忆回答，而是在回答前先从私有知识库里检索相关片段，再把这些片段作为上下文交给模型。

一个最小 RAG 链路通常包含五步：加载文档、切分 chunk、生成 Embedding、写入向量库、检索并生成回答。加载文档负责把 Markdown、PDF、网页等资料变成统一文本。切分 chunk 负责把长文档拆成适合检索的小段。Embedding 负责把问题和 chunk 都变成向量。向量库负责保存向量并执行相似度搜索。最后，生成阶段必须基于检索到的上下文回答，并给出引用。

RAG 适合处理企业内部文档、项目知识库、客服知识库、产品手册和学习笔记。它不能保证一定正确，因为检索不到、chunk 切得不好或生成阶段忽略上下文都会造成错误。好的 RAG 系统会要求回答引用来源，并在证据不足时明确说不知道。

在学习阶段，可以先用本地向量算法模拟 Embedding 和 Vector Store。这样可以先理解数据流，再替换成 OpenAI Embeddings、Chroma、pgvector 或其他生产级组件。
