# Chunking 分块策略

Chunking 是把长文档切成多个小片段的过程。RAG 中的检索单位通常不是整篇文档，而是 chunk。chunk 太大时，向量会混入太多主题，检索结果可能不够精确；chunk 太小时，片段上下文不足，答案可能缺少关键条件。

常见参数有 chunk size 和 overlap。chunk size 表示每个片段大约包含多少字符或 token。overlap 表示相邻 chunk 之间重复保留多少内容。overlap 的作用是减少边界切割造成的信息丢失，例如一个定义刚好被切在两个 chunk 之间时，重叠区域能保留上下文。

粗略经验是：短问答知识库可以使用较小 chunk，例如 300 到 600 字；长篇解释型文档可以使用较大 chunk，例如 800 到 1200 字。实际项目应该用测试集评估，而不是只凭直觉选择。

本示例会对比两种策略：small 策略使用较小 chunk，适合精确定位；large 策略使用较大 chunk，适合保留更多上下文。两种策略都会使用 overlap，避免切分边界丢失信息。
